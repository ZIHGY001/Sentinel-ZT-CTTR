## 已确认并修复的问题

下列为内部修复优先级，不是 CVSS 评分，也未分配 CVE。

| 编号 / 优先级 | 基线复现 | 修复及条件 |
| --- | --- | --- |
| R3-01 / 高：IOC 到期后仍可审批 | 将匹配 IOC 设置为分析后 1 秒到期，在 2 秒后审批同一计划，旧版仍接受。前提是具有资产配置和合法审批密钥，不是远程无认证执行。 | 动作绑定具体 IOC 及其实际对端观测；审批和执行检查来源字段、有效期、撤销标记、最低置信度和匹配关系。审批截止不晚于 IOC、证据、计划或所用基线到期。预检期间到期时不发出修改请求。 |
| R3-02 / 中：初始化失败泄漏响应锁 | 注入 sqlite3.connect 失败后，同进程再次打开日志提示 busy，因为原锁描述符未释放。 | 任意初始化失败关闭已建连接并释放锁，close 可重复调用；既有审计不会被删除。 |
| R3-03 / 中：响应状态文件保护不一致 | 将 response.sqlite3 硬链接到另一普通文件，旧 Journal 接受并写入同一 inode；原代码还直接 chmod 数据库，而未先拒绝不安全属性。 | 数据库、锁文件要求私有、当前用户拥有的单链接普通文件；密钥拒绝硬链接，非阻塞打开后验证类型，避免 FIFO 读阻塞。需要本地文件写权限或错误部署，不构成无认证远程提权。 |
| R3-04 / 低：文章来源路径逃逸 | 绝对 GitHub 文章 URL 含 articles/../../… 时通过旧前缀检查，浏览器可把路径解析到其他仓库。 | 逐路径组件验证、拒绝点路径/反斜杠/控制字符/二次编码歧义，再生成规范的限定仓库文章 URL。不是任意代码执行；主要修复来源标注完整性。旧本地知识索引需重新生成。 |
| R3-05 / 低至中：STIX 创建者冲突仍受顺序影响 | 三个同 ID 版本分别含创建者 A、未提供创建者、创建者 B；六种顺序中两种被旧代码接受。 | 独立累计每个 ID 的已知创建者，不再只与当前选中的最新版本比较；六种顺序均拒绝冲突。 |

IOC 绑定选择情报寿命与同一条观测新鲜度的共同有效期，不能把另一条更晚的网络记录借给已过期情报。该检查限定开始执行的时间；执行后的封禁持续时间仍由审批中的内核 TTL 控制。没有实现在线情报撤销轮询。

## 新能力与安全设计

- B101：内部远程服务访问偏离资产角色的批准目标/端口/协议路径。
- B102：滑动窗口内，基线外远程连接达到不同目标数量门槛，重复目标不重复计数。
- B103：成功的授权变更偏离精确操作者、动作、目标账户和目标权限组合。
- B104：成功的权限提升偏离精确用户、目标身份和程序路径。
- C101：同资产、精确相同活动账户的异常权限变化后，15 分钟内出现基线外远程访问。

这些模型不要求 IOC。资产角色取自审核策略，不取自日志自报字段或 Quake；正常路径只作用于新基线模型。关键资产提高研判优先级，但仍不自动授予执行权限。

模板默认禁用。配置严格拒绝未知字段、类型混淆、无效数值、未知角色绑定和过长审核窗口；profile 最长 90 天。精确临时例外最长 24 小时，要求资产、全部匹配维度、原因、审核人和起止时间。命中例外留存证据；不支持用旧全规则 suppressions 关闭 B101–B104/C101。例外不覆盖显式 authorized=false，不屏蔽其他检测或 IOC。

未配置、草案、过期、未来、源资产不匹配或遥测不足都明确报告覆盖缺口。登记而无日志的资产也出现在覆盖表。绑定基线的访问请求不能使用过期基线或完全不可评估的行为输入得到允许结果。

基线有效期也约束本机审批和云脉交接截止。无 IOC 高风险行为可生成手工调查计划和云脉待审核交接；本机 nftables 自动适配器仍保留有效 IP IOC、近期独立行为、资产授权、签名审批与显式 --live 的门槛。Pi 自动摘要不包含新增 observed 字段、IP、操作者、目标用户或角色名称。

模型的 ATT&CK 技术映射、完整数据契约、配置与操作说明见 [行为基线指南](BEHAVIOR_BASELINES.md)。这是本项目的实验性映射，不代表 MITRE 认证或完整攻击链覆盖。

## 升级与实际边界

1. 停服务并备份整个私有工作目录。保持数据库、签名审计、动作缓存和审批材料完整；遇到文件属性或签名不一致时先排查，不通过清空日志解决。
2. 旧计划缺少新的 IOC 绑定；使用 v0.3.0 重新分析、生成和审批。已有历史调查不会自动重算。重新生成旧知识索引与云脉交接单。
3. 生产基线必须由业务与安全人员共同审核。示例使用文档保留网段、合成账户和演练时间，不能直接作为真实资产权限。模板校验成功不等于真实审批。
4. 当前为批次分析，不是持续采集或实时告警推送服务。身份/提权日志需按标准 JSONL 规范化；没有直接集成 Windows Security EVTX、Linux auditd 或云脉审计采集。
5. 未执行真实 nftables、云脉策略或 SDK 操作；Quake 实际账号、模型凭证、真实业务误报率、检出率、性能 SLA 和连续运行负载尚未验证。合成演练不能支持未知攻击覆盖率或效率提升百分比。
6. 日志真实性、资产身份映射、审批密钥和主机权限仍是外部信任前提。同资产/同账户时间关联不是进程或会话因果证明。审计链无外部 head_mac 锚定时，仍不能检测完整替换或尾部截断。
7. 交付包含代码、构建产物、测试、文档和截图；没有运行 GitHub 远端 CI、提交 commit、创建 PR 或发布 release。

本报告不宣称“无漏洞”。本轮确认的缺陷已修复并回归，实际生产接入与检测覆盖仍需现场验证。
