## 确认问题与修复

以下等级是结合当前部署边界的内部修复优先级，不是 CVSS 分数；本轮未申请或分配 CVE。

| 编号 / 优先级 | 复现与影响条件 | 修复行为 |
| --- | --- | --- |
| R2-01 / 高：旧行为支持新处置 | 同资产 B001 行为已过去 3600 秒，而实际网络对端 IOC 仅 2 秒前出现；默认行为时效 900 秒，旧计划仍可标记 `executable=true`。仍需合法策略、资产授权和签名审批才能进入 CLI 实际执行。 | 要求同资产完整的新鲜 B 类 finding；计划绑定规则、全部证据 ID 与最早观测时间，审批及执行重新检查。C 类链中的新 IOC 不算新行为。 |
| R2-02 / 中：重新分析刷新访问上下文 | 使用合法身份、设备与资源权限请求，对 10 小时前的干净日志刚完成分析，旧 `access` CLI 可返回 allow。不是网页 Bearer 鉴权绕过。 | 分析摘要及生成时间之外，还要求请求资源存在新鲜的原始观测。缺失时返回验证错误，不产生允许结果。 |
| R2-03 / 中：缓存删除后动作重放 | 本地 `actions` 行被删除，但原签名审计历史仍有效；同一计划/审批在有效期内可被再次执行。前提是状态库被改动或部分损坏，不是未认证远程提权。 | 验证签名链后，以该动作的签名历史和缓存共同拒绝重复执行；回滚缓存状态必须与签名历史一致。 |
| R2-04 / 中：回滚失败缺少持久记录 | 已执行动作回滚命令超时/失败，先前代码未落盘回滚意图及不确定结果。实际内核可能已经完成删除，不能认定“未发生变更”。 | 执行前提交 `rollback_intent` / `rollback_pending`；失败提交 `rollback_uncertain`，提示人工核对。成功仍留存 `rollback_success`，已成功回滚可重复查询。 |
| R2-05 / 中：STIX 撤销受顺序影响 | 相同 ID、modified 的活动与撤销对象，输入顺序不同会改变是否命中。无效“撤销后再激活”版本也可能让撤销失效。 | 同 ID/modified 的冲突表示拒绝整批导入；同批任一版本撤销后保持撤销。拒绝已观察到的不同创建者冲突；无法安全规范化的撤销模式不再静默跳过。 |
| R2-06 / 中：STIX 分发标记丢失 | 原导入统一使用 AMBER，包括附带 RED 标记的对象。可能误导分析员对导出材料的分发判断；本轮未观察到实际泄露。 | 解析同 Bundle 的 TLP marking-definition，保留最高限制级别。无法解析、自定义或 granular 标记保守标记 RED，并要求复核原始约束；不宣称实现完整分享策略。 |
| R2-07 / 低至中：解析异常与歧义 | 极端时区时间产生 UTC 溢出，分析接口返回 500；字面 U+2028 等分隔符被当成 JSONL 换行；1 MiB 行预算按字符计数；CSV 重名列覆写值、错列；STIX 对象类型错误；URL 端口 0 被静默移除。 | UTC 和默认到期时间溢出转为验证错误；按 LF/CRLF 切物理行、保留 Unicode 内容和原行哈希；行预算按 UTF-8 字节计算。严格验证 CSV/STIX 结构，拒绝端口 0、空凭证分隔和 IPv6 zone URL。 |
| R2-08 / 中：交接复核期超出证据期限 | 行为剩余 5 秒有效时，云脉交接单仍给出固定更长复核期；关联链的近期 IOC 还可能使过期行为通过新鲜度检查。 | 使用完整 B 类行为时效；每项复核期限取配置、行为、映射到期时间的最小值，总期限取最早值。映射引用不接受首尾空白，减少标识比较歧义。未验证厂商对空白的处理方式。 |
| R2-09 / 中：交接文件无限累积 | 已认证操作员反复生成交接单，可在案例数量上限之外继续增加磁盘文件。 | 单进程锁内检查最多 500 个 JSON、总计 64 MiB；超额返回 409并保留既有材料。该预算不等同生产抗拒绝服务能力。 |
| R2-10 / 低：抑制项类型导致 500 | 向规则抑制项传入非空数组/对象，旧验证放行后出现不可哈希异常；需要已认证分析导入。 | 规则 ID、资产、原因和过期时间必须为非空字符串；错误明确拒绝。访问请求非对象也返回验证错误。 |

上述修复保持保守边界：行为发现和 IOC 时间相近并不证明因果关系，完整聚合行为的所有引用事件都须新鲜。新鲜日志不等同于可信日志，采集系统仍须在外部认证与保护。

## 关键复核方法

1. 用合成数据将行为时间设为当前时间前 3600 秒、对端 IOC 设为前 2 秒，确认计划含 `fresh_behavior_evidence_required` 且不可执行；将行为恢复为近期，合法审批可通过；等待行为到期后，即使对端与审批仍新鲜，也拒绝执行校验。
2. 行为设为前 901 秒、IOC 前 2 秒，二者仍形成 C001 时间关联，确认云脉交接项目为 blocked；行为/映射各仅剩 5 秒时，交接截止时间同步缩短。
3. 使用模拟 nft 执行器完成应用和回滚，再删除动作缓存行；确认原签名历史阻止重放。伪造缓存为 rolled_back 也不能隐藏尚未回滚的动作。
4. 在模拟回滚中注入超时，确认持久签名历史包含 intent 与 uncertain，后续合法重试在所有权检查通过时完成。测试不会调用真实 nftables。
5. 交换 STIX 冲突记录的输入顺序，均应拒绝；撤销后出现非法活动版本仍保持撤销；正常更新仍选择最新版本。附带 RED 标记被保留，未解析标记返回限制性提示。
6. 用 U+0085/U+2028/U+2029、极端时间、UTF-8 多字节大行和畸形 CSV/STIX 验证明确失败或正确保留；检查原日志行哈希不变。API 输入变异不得产生 5xx。

回归位于 `tests/test_audit2.py`，其余原有测试仍保留。

## 升级与遗留边界

- 停服务备份整个私有工作目录；保留原签名日志、动作缓存、审批与材料，不通过清空记录绕过检查。
- v0.2.1 及更早响应计划缺少行为绑定字段。用 v0.2.2 重新导入原始材料、分析、生成计划并重新审批。存储的历史案例不会自动重算；不要编辑旧计划补字段或改时间。
- 旧云脉交接单应重新生成；交接截止时间是人工复核边界，JSON 不是厂商导入格式，也不是有效执行审批。没有实现云脉管理 API、SDK 注销或真实租户处置。
- 所有真实 nftables 路径仅用模拟执行器验证。跨平台、真实云脉租户、连接器、会话切断、Quake 实际请求、真实模型调用及持续负载仍需现场测试。
- 审计链没有外部锚定时仍不能发现完整替换或尾部截断；需独立保存 head_mac。持有签名密钥或主机 root 的攻击者超出本地防篡改机制的保护范围。
- STIX 仍仅支持规定的单一等值模式；撤销约束作用于当前导入批次，没有跨批次撤销存储。未知分发标记必须人工检查，不以 RED 替代原始条款。
- GitHub Actions 配置随包交付，但本轮没有运行远端 CI、提交 commit、创建 PR 或发布 release。

STIX 版本与撤销规则参考 [OASIS STIX 2.1 规范](https://docs.oasis-open.org/cti/stix/v2.1/os/stix-v2.1-os.html) 的 3.6 节；标记结构见 7.2 节。本工具对同版本冲突采用拒绝策略，并非规范要求的唯一处理方式。
